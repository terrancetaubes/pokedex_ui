# Agent change log: pokedex_ui

Each entry records one change made by an agent. Newest entries first.

| Date | Change | Reason | Files |
|---|---|---|---|
| 2026-11-21 | Redesigned `src/index.html`, `src/app.js`, and `src/styles.css` to look like a modern chat app. The page now has a sidebar with in-memory chats and a "New chat" button, a top bar with the account and Sign out, a welcome view with suggestion chips, a message thread (user right, answer left, sources below), and a bottom composer (Enter sends, Shift+Enter adds a line, 2000-character limit with a counter). Light and dark modes follow the system setting. Sign-in and the backend call are unchanged in contract. | Requested Claude-style UI. Chats stay in memory so that no question text is stored in the browser. | `src/index.html`, `src/app.js`, `src/styles.css` |
| 2026-11-21 | Changed sign-in from a popup to a redirect. `signIn()` calls `loginRedirect` and sends the user to the Microsoft login page. `signOut()` calls `logoutRedirect` with the UI origin. `start()` calls `handleRedirectPromise()` after `initialize()` to finish the return. Silent-token failures that need the user now call `acquireTokenRedirect` (the popup fallback was removed). Sign-in is enabled in every state. In an unconfigured or still-starting build, a click shows a message and does not redirect. "New chat" is enabled in every state and opens a blank chat. Verified with stubs in headless Edge: placeholder build (message shown), signed-out build (redirect called), and new chat (thread cleared, welcome shown). The real Microsoft login was not tested. | The user asked for these behaviors. A redirect works without popup permission. Trade-off: in-memory chats are lost at each redirect. Documented in `docs/DESIGN.md`. | `src/app.js`, `docs/DESIGN.md`, `AGENT_CHANGELOG.md` |
| 2026-11-21 | Changed the signed-out and not-configured states so the controls stay visible. The sign-in button and the sign-in panel show in every state and are disabled when sign-in cannot work. The composer is always visible and accepts text only when signed in. "New chat" and the suggestion chips are disabled when signed out. The sign-in text explains the state. Removed the initial `hidden` on the composer in `index.html`. Verified in headless Edge with the placeholder config, a signed-out stub, and a signed-in stub. | The user could not find the sign-in button, the message box, or a working "New chat" in the placeholder build. Those controls were hidden, and "New chat" did nothing. Disabled controls with a reason show the user what is missing. | `src/app.js`, `src/index.html`, `src/styles.css`, `docs/DESIGN.md` |
| 2026-11-21 | Fixed `src/app.js`: the page does not start with placeholder settings (shows a message instead); a silent token request falls back to a popup only for `InteractionRequiredAuthError` (network errors are shown); API errors show a message by status code; the answer is checked for type before it is shown. | The old code opened a popup on any silent-token error, and it sent placeholder settings to MSAL. | `src/app.js` |
| 2026-11-21 | Pinned the MSAL script to `@azure/msal-browser@3.30.0` with a `sha384` integrity hash, instead of the floating `@3` tag. | A floating tag can change under the page without a review. The hash makes the browser refuse a changed file. | `src/index.html` |
